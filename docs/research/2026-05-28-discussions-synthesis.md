## TROUVÉ : la trick centrale qui débloque 0.91 → 0.947 (+3.7pp)

Topic `699182 - defensive-pipeline-0.950-CV` — résumé d'un Kaggler grade-de-base avec pipeline 0.95019 CV AUC :

> "96.32% of test (Year, Race, Driver) units have at least one lap in train. For each test row [...] you can look up *other* laps from the same driver-race-stint in the training set and compute aggregates: max tire age reached in this stint, slope of lap times, whether `PitStop=1` was already observed. These features are computed from train rows only and merged onto both train and test by the unit/stint key. They're leakage-resistant because the test set was generated by random row-sampling within units, not by holding out whole races. Adding these features lifted LightGBM CV AUC from ~0.91 (base features only) to 0.947 (with stint aggregates). **Larger lift than any tuning step gave me later.**"

### Vérifié dans NOTRE data (2026-05-28)

| Granularité | Test units | Présents train | % rows test couverts |
|---|---|---|---|
| `(Year, Race, Driver)` | 37 038 | **35 674 (96.32%)** | **99.09%** |
| `(Year, Race, Driver, Stint)` | 83 812 | 72 859 (86.93%) | 92.79% |

→ **Notre dataset matche EXACTEMENT** le claim. 99.09% des test rows peuvent recevoir des features aggregates depuis train sur leur (Y,R,D), 92.79% au niveau (Y,R,D,Stint).

### Aggregates candidates (issus du post + notre EDA)

Pour chaque test row, lookup train rows même (Y,R,D) puis (Y,R,D,Stint) et calculer :

| Feature | Calcul | Pourquoi |
|---|---|---|
| `train_unit_max_TyreLife` | `train_rows.TyreLife.max()` | Max tyre age déjà observé sur cette unité — proxy pit décision |
| `train_unit_max_Stint` | `train_rows.Stint.max()` | Combien de stints déjà observés → progression race |
| `train_unit_PitStop_any` | `train_rows.PitStop.any()` | Pit déjà observé sur cette unité ? |
| `train_unit_PitNextLap_mean` | `train_rows.PitNextLap.mean()` | Target encoding au niveau unité (CV-aware) |
| `train_unit_LapNumber_max` | `train_rows.LapNumber.max()` | Course finie ? |
| `train_stint_max_TyreLife` | (Y,R,D,Stint) | Max tyre dans CE stint — signal direct |
| `train_stint_PitStop_any` | (Y,R,D,Stint) | Pit déjà fait ce stint |
| `train_stint_n_rows` | (Y,R,D,Stint) | Combien de laps observés ce stint dans train |
| `train_stint_LapTime_mean_diff` | `current.LapTime - train_rows[same_stint].LapTime.mean()` | Pace relative au stint |
| `train_stint_RaceProgress_min/max` | (Y,R,D,Stint) | Window du stint dans la course |

**Warning leak-free** : Ces aggregates sont calculés depuis train rows pour TOUS les rows (train + test). Pour les train rows, exclure soi-même via `leave-one-out` ou utiliser un k-fold CV target encoding (sinon overfit massif via target encoding direct).

→ **Cette FE seule peut nous faire passer de OOF 0.9294 (LB 0.94457) à ~0.95 OOF (LB 0.951-0.953).**

## Autres findings critiques

### 1. Per-year CV AUC = mandatory monitor

Topic `defensive-pipeline-0.950-CV` :

| Year | CV AUC reported |
|---|---|
| 2022 | 0.909 |
| **2023** | **0.934** (highest!) |
| 2024 | 0.924 |
| 2025 | 0.924 |

> "2023 is actually the *highest* AUC year, which is the smoking gun that the model is using Year as a regime indicator (predict near zero whenever Year=2023). That's legitimate signal because 2023 really does have a different base rate, but if you only look at overall AUC you miss that one year is being predicted by a single feature."

**Implication pour notre kernel submit-02** : logger AUC par Year dans le fold loop. Si 2022 < 0.92 et 2023 > 0.93 → diagnostic Year-as-regime, possiblement à hiérarchiser.

### 2. Three GBDTs ≠ ensemble (diversity check)

Topics `defensive-pipeline` + `triple-gpu-ensemble-l2-stacking` :

Pairwise Spearman correlations OOF :
| | LGBM | XGB | CAT |
|---|---|---|---|
| LGBM | 1.000 | **0.981** | 0.967 |
| XGB | 0.981 | 1.000 | 0.957 |
| CAT | 0.967 | 0.957 | 1.000 |

> ρ(LGBM, XGB) = 0.981 is too high. Two models that close to each other don't add diversity to a blend; they amplify whatever shared errors they have.

Stack coefficient on XGBoost = **-1.41** → le stacker "trust the disagreement backward" car XGB = noisy LGBM.

**Fix prescrit** : ajouter modèle d'une **famille différente** (NN). Auteur utilise **RealMLP** (PyTabKit). Blend LGBM + CAT + RealMLP > LGBM + CAT + XGB.

> "Ensembling three implementations of the same algorithm family is not the same as ensembling three algorithms. Gradient boosting on a fixed feature set converges to similar functions regardless of whether the implementation is LightGBM, XGBoost, CatBoost, or HistGradientBoosting. The ensemble benefit comes from architectural diversity, not implementation diversity."

### 3. Rank-average ÷ calibration sanity check

> "Rank-averaging output is uniform on [0, 1] by construction. Overall mean ≈ 0.5. If your submission verification includes a per-year mean sanity check (which mine did → "2023 mean should be ≈ 0.03 like the training base rate, others should be ≈ 0.28"), rank-averaged predictions will fail that check even though the ranking is correct. **Fix: isotonic regression on the OOF predictions, then apply the calibrator to the test predictions.**"

→ Si on fait un ensemble par rank-average, calibrer ensuite par isotonic regression sur OOF.

### 4. External Aadi Gupta dataset — incohérences propres

Topic `inconsistencies-original` (auteur appellé "brocolli beef" par d'autres posts) :

Test consistency dans Aadi Gupta v4 (3 invariants F1) :
- `LapTime_Delta[i] == LapTime[i] - LapTime[i-1]` si pas pit
- `Position_Change[i] == Position[i-1] - Position[i]`
- `PitNextLap[i] == PitStop[i+1]`

**Result** : ces invariants ne tiennent PAS sur de nombreux (driver, race, year). Le dataset Aadi Gupta a ses propres bugs de dérivation. **Pas pure FastF1 raw.** 92% match avec FastF1 mais 8% diverge.

Un autre commentateur : *"209k rows ont incohérence où Stint diffère de 2 vs PitStop count."*

**Implication** : utiliser Aadi Gupta MAIS ne pas considérer comme "ground truth". Garder le flag `IsOriginalData=1` qui permet à CatBoost de re-pondérer.

### 5. External data hurts CV but helps LB

Topic `submission-generalization-LB` :

> "The external dataset has a smoother distribution. So the external data actually hurt local CV while improving LB. It is close enough to transfer useful structure, but different enough to regularize the ensemble."

→ Ne pas s'inquiéter si CV baisse légèrement après ajout Aadi Gupta. Le LB importe.

### 9. PitStop exclusion (controversé)

Notre EDA #01 LEAK CHECK avait conclu : 81.7% match `shift(-1)(PitStop) == PitNextLap` → "non-trivial leak, feature à garder". Mais cette personne l'a SHIFTÉ pour safety. **Optional A/B test à faire dans submit-02 (with vs without PitStop).**

## Plan submit-02 RÉVISÉ (post-discussions)

### Strategy 1 — "killer trick FE" (recommandée, J-3 viable)

**Adds** (vs submit-01) :
1. **(Y,R,D) and (Y,R,D,Stint) train-lookup aggregates** (10-15 features, leak-free via k-fold target encoding pour la partie train) ← THE BIG ONE
2. **Aadi Gupta external data** concatenated to train, flag `IsOriginalData`
3. **Domain features** (~10) : EstimatedTotalLaps, LapsRemaining, TyreAgeRatio, PitWindowPressure, etc.
4. **Cross-categoricals** (~9) : Race_Year, Compound_Stint, Driver_Race, etc. + frequency encoding
5. **CatBoost params tunés** : depth=8, lr=0.018, l2_leaf_reg=8.5, early_stopping=500, `auto_class_weights="Balanced"` (TEST sans aussi)
6. **CV** : StratifiedKFold(5, shuffle, seed=42) au lieu de GroupKFold
7. **Per-year AUC monitoring** dans fold loop
8. **Per-year mean sanity check** post-prediction

**Cible** : OOF AUC 0.949-0.952, LB 0.950-0.952. **Gap CV-LB attendu ~0** (stratified random matche test split).

### Strategy 2 — TabPFN-3 single model (alternative quick)

**Steps** :
1. `pip install tabpfn` dans kernel
2. Load TabPFN-3 classifier
3. 5-fold StratifiedKFold
4. No FE
5. Submit

**Cible** : OOF 0.951 reported, LB ~0.951.

**Tradeoff** : aucune pédagogie ML classique, juste un appel API. Mais ship-friendly si on est short en temps.

### Strategy 3 — Hybrid CatBoost+FE+TabPFN ensemble (J-1 si temps)

Train both pipelines, blend OOF via Logistic Regression meta-learner, isotonic calibrate.

**Cible** : OOF 0.953-0.954, LB 0.953-0.954.
